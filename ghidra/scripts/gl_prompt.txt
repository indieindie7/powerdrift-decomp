Sega arcade game Power Drift (1988, Y-Board, three 68000 CPUs: main = game logic, course loading, car physics, AI; suby = road/rotation layer, palette, attract, ranking, name entry; subx = sprite list builder, backup RAM, ROM/RAM test). Every function is already hand-named. Now we name RAM globals.
Each LIST line is "0x<addr> refs <n> | <cpu>: <function names that use it> | ..." (shared RAM 0x0c0000-0x0cffff, seen by all CPUs) or "0x<addr> refs <n> fns <k>: <functions>" (work RAM of one CPU, addresses 0xffffxxxx / 0x1fxxxx).
Decompiles: <project>/ghidra/decomp_main.c, decomp_suby.c, decomp_subx.c. Grep "DAT_<addr8>" (8 hex digits, e.g. DAT_000ce09c or DAT_ffff8000) in the right file, and Read a few lines around a hit (offset/limit) when the function names alone do not tell you the role. Never Read those files whole.
Known: 0x0ce09c = game mode word; 0x0cff88 = sound queue ring; 0x0cff60 score, 0x0cff64 high score, 0x0cff68 score to add; 0x0cff0c vblank flag (subx); 0x0cff06 main-ready flag; NOTES with more context: <project>/NOTES.md (Grep it for an address without the 0x0 prefix, e.g. "ce09c").
Write OUT (Write tool), one line per LIST address you can characterise: "0x<addr> <name>" with the address exactly as in LIST, name a C identifier of max 40 chars: prefix sh_ for shared RAM, g_ for work RAM (add the CPU for work RAM: g_suby_..., g_subx_..., g_main_...). Names must be unique in OUT. If it is clearly a field of a struct/array that starts at a lower LIST address, name it <base_name>_<hexoffset>. Do not guess wildly: a plain but true name (sh_car_state_ea3a) beats a wrong specific one. Skip an address only if you have no evidence at all. Lines only, no comments. Final reply: number of lines written and skipped.
